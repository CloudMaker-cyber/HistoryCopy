# 开发日志使用说明

## 目录规则

- 每个工作日一个文件,命名格式:`YYYY-MM-DD.md`
- 例如:`2026-08-02.md`

## 日志格式

```markdown
# 开发日志 YYYY-MM-DD

## 今日待办
- [ ] 事项 1
- [ ] 事项 2

## 今日完成
- [x] 事项 1(完成说明,可带文件路径)
- [x] 事项 2

## 遗留问题 / 阻塞
- 描述问题及下一步

## 明日计划
- 事项
```

## 填写规则

1. **每次会话开始**:打开/创建当日日志,先列出"今日待办"(承接昨日遗留)
2. **每完成一项**:把对应待办勾选,并挪到"今日完成"下,附简短说明
3. **发现新问题**:立即写入"遗留问题/阻塞"
4. **会话结束**:填写"明日计划",勾掉完成的待办
5. 涉及文档变更时,同步更新 `docs/` 对应文档并在此注明

## 与文档的关系

| 文档 | 用途 |
|---|---|
| `docs/requirements.md` | 需求标准,变更先改这里 |
| `docs/tech-spec.md` | 技术方案,实现依据 |
| `docs/design-spec.md` | 界面规范,UI 实现依据 |
| `docs/dev-plan.md` | 开发计划,阶段勾选与验收 |
